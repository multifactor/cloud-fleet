# claude-fleet — implementation contract

This is the single vocabulary every file in this plugin is written against: names, config keys,
tracker operations, CLI subcommands, state layout, flag schemas, and the style + redaction rules for
prose. If a playbook, adapter, doc or module disagrees with this file, this file wins and the other is
a bug. Keep it boring and exact.

## 1. Names

| thing | name |
| --- | --- |
| plugin | `claude-fleet` (marketplace `claude-qa-skills`) |
| commands | `/fleet` (work tickets), `/fleet-check` (review PRs, file gated tickets) |
| CLI | `node "${CLAUDE_PLUGIN_ROOT}/src/cli.mjs" <cmd>`; humans: `npx claude-fleet <cmd>`. Written as `fleet <cmd>` in prose. **Never a bare `fleet` bin** (collides with Rancher Fleet / fleetctl). |
| env prefix | `FLEET_` — one prefix, no aliases carried over from the private original |
| roles | `working` (a session working one ticket) · `testing` (a session that owns a shared dev-server slot) · `checker` (a session running a `/fleet-check` slice) |
| people | **the operator** (the human running the fleet) · **the launcher** (the `/fleet` or `/fleet-check` session) · **a session** (a spawned working/testing/checker Claude Code) · **a worker** (a subagent or cloud sandbox inside `/fleet-check`) |
| example issue key | `ABC-1234` (regex example `[A-Z][A-Z0-9]+-[0-9]+`) |
| example repo / org / person | `github.com/acme/app` · `acme` · `ada` (branch prefix), `ada@example.com` |
| example dev URLs | `https://{branch}.dev.localhost` (per-branch host) · `http://localhost:{port}` (fixed port) |
| example services | postgres container `app-postgres` on 5432 |
| example dates | `2026-03-14` (never a real incident date) |

**What must never appear in a published file**, by category — the company this tool was extracted
from, its domains and hosts, its products and internal codenames, any person's name or email, its
issue-key prefix, its source-tree directories, its infrastructure and vendor names, and any absolute
path from a contributor's machine. Use the placeholders above instead.

**One exemption, and only one:** the name of the organisation that *publishes* this repository may
appear in legal and package-identity metadata, in exactly six files — `LICENSE` (the copyright
holder), the two `.claude-plugin` manifests, the install command in `README.md`, the schema's
canonical `$id` URL in `schema/fleet.config.schema.json`, and `scripts/build-schema.mjs` which
generates that `$id` — because a copyright holder, an install path and a schema identifier are not
leaks, and a reader cannot install the plugin without the address. The redaction fixtures are a
seventh case by construction: an allowlist has to quote what it allows. It appears nowhere else: not
in a playbook, not in an adapter, not in a doc, not in a code comment.

⛔ This used to say four files and end "It appears nowhere else", which was **not true of the tree it
describes** — the schema `$id` and its generator had carried the name since the schema was generated,
and nothing noticed because the prose gate reads only `.md`/`.txt` under four directories. The
manifests were outside every gate for the same reason. So the exemption is no longer a rule for
authors: `docs-redaction.test.mjs` walks **every file `git` will publish** and fails on a denied
identifier in any file not on the list above. Adding a seventh file means changing that list, which
is a change to this exemption and needs the argument the first six got.

The enforcement is `test/docs-redaction.test.mjs` + `test/playbook-brands.test.mjs`, and the token
list lives **hashed** in `test/fixtures/redaction-{exact,proper}.txt` — a published plain-text
denylist would leak the very names it guards. `redaction-patterns.txt` holds the patterns that
describe a *shape* rather than a secret (an issue-key regex, an absolute Windows path) and are safe
to read; `redaction-allow.txt` holds the handful of strings that must appear anyway. A hit outside a
fenced ```example``` block fails the build. To check a token you are unsure about, hash it:
`node -e "console.log(require('crypto').createHash('sha256').update(process.argv[1].toLowerCase()).digest('hex').slice(0,16))" <token>`
and grep the fixtures.

## 3. Config

Two layers. **Project**: `<repo>/.fleet/config.json` (committed) + optional `.fleet/config.local.json`
(gitignored). **User**: `%APPDATA%\claude-fleet\config.json` / `$XDG_CONFIG_HOME/claude-fleet/config.json`
(override `FLEET_CONFIG_HOME`), shaped `{version, defaults, repos: {<repoKey>: {..., checkouts: {<path>: {...}}}}}`.
`repoKey` = normalised origin (`host/owner/name`, lowercase, `.git` stripped, scp form normalised);
fallback `local:<name>@<sha1(gitCommonDir)[0:8]>`.

Precedence: defaults → project → project-local → user defaults → user repo → user checkout → `FLEET_*`
env → CLI. Every key has `scope: project | user | either`. A `user`-scope key in a project file is
**ignored with warning `config.scope.leak`**; a `secret` key there is an **error**. `$pinned: [...]` in
the project file makes those keys non-overridable by the user layer (env/CLI still win, loudly).
Env name = `FLEET_` + key path upper-snake (`commands.devServer` → `FLEET_COMMANDS_DEV_SERVER`); blank
env = unset. Scalars and `string[]` (comma-joined) only.

## 4. State directory

```

  sessions/<label>.json             the fleet registry + session descriptor (one file per session)
  locks/<pool>/<slot>/holder.json   mkdir-mutex; staleness by timestamp ONLY; heartbeated by the shim
  flags/done-<label>.json · flags/blocked-<label>.json  (+ a one-line .txt twin for tailing)
  tickets/<KEY>.json · .md          offline ticket cache written by `fleet ticket cache`
  tracker-outbox/*.json · applied/  ops a session could not perform; drained by the launcher
  queue.txt                         autowave input, one key per line, priority-sorted
  intake-refused.jsonl              tickets refused at intake, with reasons
  sweeps/<sweepId>/                 /fleet-check: manifest.json worklist.tsv ledger.tsv slices/ filed/ findings/ findings.jsonl
                                    dups.tsv xref.tsv shots/ _sweep/ outbox/ audit/ RESUME.md
  install-reference.json            per-package file counts of the primary checkout, keyed by lockfile
                                    hash — the install proof (§3); written by `fleet up` and by
                                    `fleet doctor --verify-primary`
  nm-donor/                         warm node_modules donor (install.donor)
  dev-pages/<KEY>.html              scratch review pages (artifactsDir default)
  wip/<label>-<stamp>.patch         guardian work-in-progress snapshots — NEVER `git stash` (refs/stash is
                                    shared across worktrees, so a stash in one session pops in another)
  fleet-manifest.json               the guardian's "what was this fleet" record, for after a crash
  watch.status.json                 the supervisor's last pass, read by `fleet status` and the launcher

```

Session descriptor (`sessions/<label>.json`) fields — written by the launcher: `id label role worktree
branch issue ticketFile backendRef createdAt transcriptDir tracker{id mode adapterPath scope states
assignee} playbook stateFile testingUrl testingUrls slot? port? paths{stateDir flagsDir outboxDir
artifactsDir} readyFlag agent model sweepDir? slice?`; added by the shim as it runs: `shimPid agentPid
pgid startedAt exit?`; added by the reconciler: `liveness ("alive"|"dead") deadAt? reconciledAt?`.

`backendRef` is backend-private addressing and its shape is the backend's business, with one
requirement: it must identify the SPAWN, not the label, so a relaunched session cannot be confused
with the one it replaced. The liveness fields are separate from the working/ready/blocked state the
hook writes into `stateFile` — one is "is this process alive", the other is "what is the agent
doing", and putting them in one field makes the reconciler and the status hook overwrite each other.

Mirrored env scalars in every session: `FLEET_SESSION=1 · FLEET_SESSION_FILE · FLEET_LABEL · FLEET_ROLE ·
FLEET_STATE_FILE · FLEET_STATE_DIR · FLEET_TESTING_URL · FLEET_TESTING_URLS · FLEET_TRACKER_MODE`, plus
`FLEET_SWEEP_DIR · FLEET_SLICE` for `checker`, plus `FLEET_SLOT · FLEET_SLOT_BRANCH · FLEET_PORT` for
`testing` — a slot's dev-server command needs its own port and `{port}` is otherwise only a URL
placeholder, so without these a fixed-port project cannot start a second slot at all. The shim deletes `CLAUDE_CODE_CHILD_SESSION` and
`CLAUDECODE`, passes `--model <fleet.model>` explicitly, and matches itself by the exact argv token
`--fleet-session=<label>`.

## 6. Tracker operations (canonical names — playbooks use these and nothing else)

```

op-2  getIssue(key) → {key,id,title,description,url,status,priority,parentId,suggestedBranch?}
op-3  resolveUser(nameOrEmail|"me") → userRef                 op-16 findIssues({group?,labels?,priority?,state?,parentIsNull?,text?,createdAfter?,limit}) → {issues[], complete}

op-8  attachLink(key, url, title)                             op-21 createProject(name) → {id,url}
op-9  cancel(key, reason)        (comment FIRST, then state)   op-22 attachImage(key, filePath, {alt, caption}) → {url, embed}
op-10 leaveOpen(key)             (explicit non-action)        op-23 setParent(key, parentKey)

```

Canonical priority: `1 Urgent · 2 High · 3 Medium · 4 Low`. Canonical state types:
`triage | unstarted | started | review | done | cancelled`, plus `ready` — the state a promoted ticket
is moved to, declared separately because a tracker may carry two unstarted-typed states (a backlog and
a to-do) and `checker.ready.state` must not have to guess between them.

⛔ **Sections are keyed by NUMBER, never by name.** op-5 and op-7 are both `setState`; a registry that
keys by name loses one and a parity check that keys by name reports a duplicate. op-7 is always
present and is op-5 applied to the in-review state.

Adapter file `trackers/<id>.md` = YAML front matter + one `## op-<n> <name>` section per supported op,
each with a `Call:` line and an `If unsupported:` line (`## op-22` also has `Strategy:` and, when REST
is involved, `Transport:`). Front matter:

```yaml
id: example-tracker             # == filename
name: Example Tracker
mcp:
  toolPrefixes: ["mcp__example__"]        # any visible tool with this prefix ⇒ connected
  install: [{label, command?, instructions?}]                  # rendered VERBATIM by the wizard
  docs: https://...
issueKey: {pattern: "[A-Z][A-Z0-9]+-[0-9]+", caseInsensitive: false, example: "ABC-1234", derive?: <field>}
#   ⛔ The pattern must match issueKey.example and NOTHING in this corpus of ordinary branch names,
#      evaluated in the declared case mode: the base branch, "develop", "release-2", testing.base,
#      "<testing.base>-2", "check/<sweepId>/<slice>", and a vcs.branchTemplate render with the key
#      removed. Case-insensitively, "[A-Z][A-Z0-9]+-[0-9]+" matches "release-2" and "testing-2" — so a
#      tracker whose keys are conventionally upper-case declares caseInsensitive: false and the CLI
#      upper-cases a candidate before matching, which accepts "abc-1234" from the operator without
#      claiming every hyphenated branch.

  resolveChildren: bool  cancel: bool  attachLink: bool  listQueue: bool  comment: bool

  findComplete: page-flag|total|link-header|all-at-once

```

## 8. Prose rules (playbooks, adapters, docs)

1. Speak only in the op names above; never a tracker tool name outside an adapter's `Call:` line.
2. Never a real issue key, PR number, commit SHA, source path, person, product or company name.
   Examples use §1's placeholders. Dates in examples are `2026-03-14`.
3. Every hard rule keeps its `⛔` and its one-sentence *why* — the why is the value. Drop the
   incident's identity, keep its shape.
4. Paths a session must use come from its descriptor / `FLEET_*` env, never from a literal — not a
   temp-dir variable, not an absolute drive path, not the agent CLI's home directory.
5. "The operator", never a name. Assignee is "the current user" (`"me"`) unless config routes it.
6. Anything platform-specific is stated for both platforms or delegated to the CLI (`fleet doctor
   --repair`, `fleet check ledger append`) — never a PowerShell-only or bash-only recipe.
7. Field notes: `### !! <symptom>` → **Saw** / a cause / **Rule** (optional **Proof / Diagnostic /
   Also**). `**Saw:**` and `**Rule:**` are literal — a reader scanning 100 notes for "what is the
   rule?" must always find it. The cause between them may carry a descriptive label when that reads
   better than the bare word (`**It is an artifact of the workflow.**`), but it must be there. A `Saw:` lets a stranger reproduce the *method* failure, never locate a *product* defect.
   Vulnerability-shaped entries keep only the Rule and a fully synthetic Saw with **no residual
   mechanism**.
8. Never tell a session to `git stash` (shared `refs/stash`), run the repo-wide killer, start its own
   server while `working`, kill by exclusion, or truncate text at a character offset.
